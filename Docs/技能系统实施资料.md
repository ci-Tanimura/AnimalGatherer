## 3. 为补齐遗漏采用的首版处理规则

以下是本次复盘给出的实施默认规则，区别于第 2 节由用户逐项确认的设计选择；若实施时发现现状不兼容，应说明证据并调整资料，不悄悄改变玩法。

- 每次按下只尝试释放一次；长按不连放。失败输入不排队，冷却结束后不自动释放。
- 失败不扣次数、不启动冷却。反向没有有效目标时返回“无目标”；缺少地图、玩家或组件引用时返回依赖错误。
- 加速是持续的全场状态，即使当时没有动物，仍可成功建立这段状态并扣次数，之后出生的动物受剩余时间影响。
- 反向立即改变箭头并保留其新方向；不在几秒后自动恢复。玩家可按原规则重新覆盖，FIFO 消退顺序不变。
- 反向不直接修改动物当前移动方向。动物已经读过的当前格不会重读；之后到达下一格中心时读取当时箭头。
- 两人几乎同时释放，按引擎实际处理顺序执行同步效果，不设置隐藏的 P1 优先权。两次加速都成功时，各扣一次，各自冷却，共享速度仍为 1.5 倍；若处理时间相同，持续时间不会额外累加。
- 使用最后一次后显示已用完，不以一个冷却结束会重新可用的环形提示误导玩家。
- 正常 Ready、Ended 阶段禁止释放技能。结束时先锁定比赛状态，之后发送 UI 事件和保存最终结果。
- 冷却及效果时长使用同一个 World 游戏时间基准。如果游戏被正式暂停，两者一起暂停；本任务不新增暂停菜单或自动暂停机制。
- 手柄断线或 HUD 重建不补次数、不清冷却；真正进入新的一局才初始化。

### 修正旧文档的判断

- 现在实现的是 180 度反向与全场加速，不是 90 度旋转和冻结。
- GAS 也适用于单机；选择自定义组件是因为本项目首版规模与维护成本，不是“单机不能用 GAS”。
- 偷取箭头仅改 Owner 会绕过接收方队列，不代表满足三箭头限制；首版不包含偷取、凭空添加或删除技能。
- 共享 DataAsset 不作为 World 或 Timer 的拥有者，不能假定资产 GetWorld 可用于查询本局动物。
- 教程当前不调用正常 StartMatch。
- 单纯把 MoveAnimal 的公式乘 1.5，不能当作已经验证了正确的高速读格。
- 主关卡 GameMode 应查实际 WorldSettings；上次记录为 BP_MainGameMode，不按旧文档直接改 GM_AnimalGatherer。
- 概念图中的格数、装饰、Goal 长度和屏幕方向不要求复制到实际关卡。

## 5. 实施架构

采用轻量自定义系统，不引入 GAS、网络复制、技能选择菜单或大型通用效果框架。

| 载体 | 职责 | 禁止放入的状态 |
|---|---|---|
| `USkillDefinition`，DataAsset | 名称、卡片贴图、次数上限、冷却、效果参数，提供无状态的同步效果入口 | 剩余次数、运行中的计时器、玩家状态、当前 World |
| `USkillSystemComponent`，每个 Controller 一个 | 运行时技能槽、玩家身份、剩余次数、冷却截止时间、失败原因、状态委托 | 全场唯一加速状态 |
| `UMatchSkillEffectComponent`，挂普通 MainGameMode | 本局共享加速倍率、结束时间、施加到现存动物、让新生动物继承剩余时长、结束清理 | 双方各自的次数与冷却 |
| `AMainGameMode` | 双方技能组、比赛阶段、初始化编排、统一结束及得分权限 | 每个技能的细节逻辑 |
| `AAnimalGatherPlayerController` | 输入转发、读取本玩家身份、受控查询实际玩家箭头坐标 | 另一玩家的可变技能槽 |
| `AAnimalBase` 与 Spawner | 实际移动倍率、读格安全、创建后的地图与共享效果初始化 | 玩家技能使用次数 |
| `UMyGameHUDWidget` 及技能卡子 Widget | 订阅状态、呈现次数/CD/全场效果、一次性反馈 | 权威计时、扣次数或执行技能 |

共享加速额外使用一个 GameMode 组件，是因为“影响未来出生动物”已经成为已确认需求。仍是一个小型单一效果载体，不扩展成通用叠加管理器。

首版实施建议选普通 `UDataAsset` 基类，开局固定两张资产由 GameMode 直接引用，不做技能池扫描或 AssetManager 额外配置。若开工时采用其他基类，在执行计划中给出实际需要，避免保留两套并行方案。

双方引用同一组定义资产、各自保存运行时槽位。2 次、5 秒及加速的 1.5 倍/3 秒只在定义资产中配置；共享效果组件接收已验证参数，不能再维护另一套可编辑默认值。首版双方加速参数必须一致，配置不合法时保持技能不可用并报告原因。

### 数据与入口约定

建议定义 `FSkillSlot`：Definition、RemainingUses、CooldownEndTime；定义 `ESkillUseResult` 区分 Success、NotPlaying、InvalidSlot、NoUses、CoolingDown、NoTarget、MissingDependency、Busy。

技能上下文显式传入施放 Controller、玩家 ID、已绑定地图和当前比赛效果组件；World 从有效运行时对象获得，不通过 DataAsset 推断，也不凭“场上第一个 MapManager”替换上下文地图。

组件提供 InitializeSkills、TryUseSkill、GetSkillSlots/GetSnapshot、GetCooldownRemaining、SetSkillsEnabled，以及状态变更/释放失败委托。初始化对本局幂等，HUD 重建不能重新初始化次数。

双方 Controller 组件在构造时创建；槽位准备必须等待 LocalPlayer 身份、地图和定义资产可用，再由普通比赛统一初始化。P1 可能先于 GameMode BeginPlay 存在，P2 在 CreatePlayer 中产生，不能依赖固定的 BeginPlay 先后顺序。Ready 阶段初始化失败就不能开启技能；教程仍默认关闭。

冷却的权威状态是 `max(0, CooldownEndTime - Now)`，不用一个只靠定时回调翻转的布尔值。组件在冷却到期时发送一次状态通知，HUD 可在冷却期间按截止时间更新秒数/遮罩；到期无需玩家再按一次才变亮。组件销毁时清理通知定时器，HUD 重建只读取快照。

效果同步执行前验证全部必要引用和目标；失败不得留下部分地图变化。施放入口带重入保护，状态更新完成后再广播给 HUD。无效玩家 ID 不静默归为 P1。

## 6. 反向技能：安全筛选与执行

给 Controller 增加只读受控查询 `GetOwnedPlacedArrowCoords`，返回当前有效的坐标副本，不把 PlaceHistory 暴露成可修改数组。

筛选必须同时满足：

1. 坐标在对手 Controller 的 PlaceHistory 中。
2. 地图一致、坐标有效、不是 border。
3. 当前 TileType 为方向箭头，当前 Owner 仍是对手。
4. 去除重复坐标，过滤被己方后来覆盖或已消退的旧记录。

依次使用显式映射 Up↔Down、Left↔Right，并调用现有 SetTileData，传回原 Owner。最多三个有效目标，不改历史，不改特殊格和预置箭头。

原有边界箭头即使 Owner=0，因为从未进入玩家历史，也不会被选中。这条筛选比“排除 border 后扫描 Owner”更可靠：以后关卡内部也可能放预置箭头。

这里保护的是当前仍保持预置状态的箭头，不是永久封锁某个坐标。现有普通放置允许覆盖内部方向格；若预置内部箭头已被玩家合法覆盖、进入该玩家历史，它就按玩家箭头参与反向。首版不额外禁止普通放置覆盖内部预置箭头。此筛选依赖普通对战不在局中重新生成 GridData 或绕过 Controller 写入玩家箭头；若实际蓝图存在这类路径，先纳入同一登记流程，不能宣称仅凭坐标历史能识别任意外部改图来源。

不调用全层 UpdateMapVisuals，不按枚举值算术转换方向。当前少量逐格刷新成本可接受，不预先重写 HISM 系统。

反向对已读过当前格的动物不会立刻反向；在脚下改箭头但动物不立即转身属于本规则。用接近下一格中心的动物测试效果，不把它误判为技能失效。

## 7. 全场加速：共享时长与新生继承

效果组件保存 `SpeedMultiplier=1.5` 与 `SpeedEffectEndTime`。成功释放时用本局游戏时间 now：

- 没有效果时建立 now+3 秒的结束时间。
- 已有效果时直接将结束时间刷新为 now+3 秒，倍率仍为 1.5；不累加旧剩余时间，不另设延长规则。
- 所有参与本局、绑定本局地图的活动 AnimalBase 子类收到当前共享倍率。
- 无动物时也保存状态；只影响游戏动物，不枚举装饰 BP_ObjectAnimal。
- 新生动物在最终地图引用和 TileSize 确定后读取同一个截止时间。出生于第 2 秒的动物只能加速约 1 秒，不能独立再获得 3 秒。
- 结束时恢复倍率 1.0，发送共享效果结束事件；切关卡、结束 PIE 或结束比赛时清理本组件计时器。

共享状态查询以 `Now < SpeedEffectEndTime` 为有效条件，到截止时间及之后返回 1.0。动物移动和新生初始化都通过同一查询取得当前有效倍率，不能只相信上次广播缓存的 1.5。恢复定时器负责清理和通知，并在回调时重新核对截止时间，避免刷新后旧回调提前结束新效果。首版按游戏帧判定边界，不声称亚帧精度；不为精确积分重写整个移动系统。

优先在 Spawner 的成功生成与地图绑定完成后调用受控初始化，避免 SpawnActor 已执行 BeginPlay、之后又修改 MapActor 的顺序导致注册到错误地图。如支持非 Spawner 创建的游戏动物，再在 AnimalBase BeginPlay 补一个幂等初始化路径。

首版不改变 MoveSpeed 基础值、不使用全局时间膨胀，因此比赛计时、光标移动、输入自动连移、Spawner 的生成间隔和 UI 动画都不会被加速。

重复使用示例：P1 在 t=0 放加速，预计 t=3 结束；P2 在 t=1 放加速，改为 t=4 结束。速度从头到尾是 1.5 倍，双方各消耗一次，各自独立进入 5 秒冷却。

## 8. 动物移动可靠性

本次重点不是加入倍率字段，而是确保动物仍按正确格子读箭头和 Goal。

- 位移、读格容差、动画速度所读取的“实际移动速度”应统一。
- 地图格长和原点取自已绑定地图；GridData 中旧 WorldLocation 不作为权威世界位置。
- 先用 1.5 倍和 60/30/15 FPS 验证，再用人工大 DeltaTime 验证跨多个格的情况。
- 若现有按最近格和容差判断不能可靠覆盖跨格，实施按移动线段经过的格中心逐段处理：到格中心时读方向/Goal，再消费本帧剩余移动距离，正确处理本帧内多次转向。
- 不仅靠无限扩大容差、限制动画速度或丢弃本帧剩余移动距离解决漏读；不能改变无技能时的原有世界轴映射。
- 每个到达的格中心只处理一次；加速恢复时不清空 LastGridCoords，不触发同格重复计分。
- 触发 Goal 后结束当前移动过程，拒绝重复得分，不继续处理已经 Destroy 的 Actor。
- 保留现有 sweep 与碰撞行为。碰撞阻止移动时不得把动物强制传送到未实际到达的下一格。
- 当前原生 RootComponent 是 USceneComponent，不能仅凭 AddActorWorldOffset 的 sweep=true 宣称存在可靠的阻挡碰撞；实际蓝图根组件和碰撞需现场核对。本次不顺带重建动物碰撞体系。
- 修正 GetCellState 的 X/Y 越界检查，防止无效坐标映射到另一行的有效格。越界返回 Empty，不能误读 Goal；不要额外发明越界扣分规则。
- 奔跑动画按倍率调整，但不得与 AnimBP 已有速度驱动重复乘 1.5。正式开工读取 BP_Animal 的网格与动画控制方式后再接入。
- 加速表现首版至少包含卡片成功反馈、共享计时条和实际速度变化；轻量动物速度标记/速度线及短音效尽量接入。复杂 Niagara 或手柄震动不作为首版功能的前置条件。

## 9. 比赛阶段、结束边界与教程

普通对战建议采用 Ready → Playing → Ended 三阶段，并以游戏时间截止点控制是否仍允许技能和进球。显示为 0 秒时必须已经拒绝新的技能和计分，不能等 UI 动画结束才锁定。

StartMatch 建立 `MatchEndTime = Now + TotalGameTime`。技能、普通对战放置、移动和 AddScore 都检查阶段及 `Now < MatchEndTime`；恰好等于截止点时拒绝。现有 AdvanceTimer 的每秒 `TimeRemaining--` 改为按同一截止点计算 `max(0, ceil(MatchEndTime - Now))`，现有整数时间委托可保留作为显示接口。到期定时器触发统一结束；其他入口先发现到期时也可进入同一幂等结束流程，不能仅等一秒刷新或仅检查阶段布尔值。直接 EndGame 仍立即结束，不必等待截止点。

准备时建立双方槽位和 HUD 快照；StartMatch 只开启使用，启动动物和比赛计时，不在每次 UI 构建时重置数据。

统一结束入口的顺序：

1. 判断是否已结束，重复调用直接返回。
2. 将阶段设为 Ended，关闭技能、普通对战放置与光标移动；清除自动连移状态。
3. 清理 Ready/Game 计时器，停止所有属于本局的受控 Spawner。
4. 结束共享加速，停止参与本局的动物移动；所有 AddScore 入口拒绝结算后的计分。
5. 固定并保存最终比分到 GameInstance。
6. 通知时间、技能状态、OnTimeUp 和音效，最后安排结果关卡跳转。

结束事件、音效、UI 委托都可能回调游戏代码，因此锁状态必须在它们之前。

教程不调用正常 BeginPlay/StartMatch。技能默认关闭且教程 HUD 不显示技能卡；保留教程现有阶段限制、得分和过关。正常对战的 AddScore/输入阶段检查必须为教程留明确兼容路径，不能直接让教程永久 NotPlaying。是否加技能教学留作以后任务，本次不改教程步骤内容。

**复核修正：保留首次分配规则，但不能完整保留现有断线路由。** 当前移除先头后会让另一只手柄自动改控 P2，与“不串玩家”的验收冲突。正式计划需包含现有 ViewportClient 内的最小修正：本局保留设备到玩家槽位的关联；断开只令对应槽离线，不将仍连接的另一只手柄补到该槽；能可靠识别的同设备重连恢复原槽。若系统将重连识别为新设备且归属不明确，必须在现场核对后确定恢复路径，不能默默替换已占用槽位。自动暂停和完整重新分配菜单仍不在首版范围。
