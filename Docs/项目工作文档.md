## 4. 主玩法运行链路

```text
AAnimalGathererGameModeBase
  └─ AMainGameMode
       └─ ATutorialGameMode

设备 → ViewportClient → LocalPlayer / EnhancedInput
     → AnimalGatherPlayerController → CursorPawn
                                  → MapManager / GridData / HISM
AnimalSpawner → AnimalBase → GridInteractInterface → MapManager
                           → MainGameMode.AddScore → HUD 委托
MainGameMode.EndGame → MyGameInstance → LV_Result
```

`AAnimalGathererGameModeBase::BeginPlay` 调用 `FixGameResolution`，设为 1920×1080 窗口模式并应用设置。小游戏直接继承 AGameModeBase，不走这条分辨率修正链。

`AMainGameMode::BeginPlay` 创建 ControllerId=1 的本地玩家，查找第一个 AnimalSpawner，初始化剩余时间，创建 HUD，然后设置移动/视角忽略标志并开始每秒一次的 Ready 倒计时。

倒计时结束调用私有 `StartMatch`：恢复输入标志、启动缓存的生成器、启动比赛计时。默认比赛 120 秒、ReadyDelay=3 秒、TimeUpDelay=1 秒。ReadyDelay 使用向上取整后的整数秒计数，并非精确浮点等待。

`AdvanceTimer` 到零后清除比赛计时器，广播 OnTimeUp，调用 EndGame。EndGame 停止缓存生成器，播放声音，把当前比分与胜负写入 GameInstance，延迟跳转 ResultLevelName（默认 LV_Result）。

Pawn 创建由 `SpawnDefaultPawnFor_Implementation` 选择 P1/P2 光标类，再初始化 MapManager、PlayerID 和网格起点；P1=(0,0)，P2=(宽度−1,高度−1)。MCP 已确认 BP_MainGameMode 绑定双方 CursorPawn 和 BP_AnimalGatherPC，当前关卡地图为20×15，因此按现有实现起点应为(0,0)和(19,14)，尚未启动 PIE 验证。

## 5. 输入、光标与箭头所有权

依据：`Private/Lee/AnimalGathererViewportClient.cpp`、`AnimalGatherPlayerController.cpp`、`CursorPawn.cpp`。

- Viewport 首次输入时把已连接设备归到键盘对应 PlatformUser，新设备连接时也执行归属修正。
- 本地玩家数大于 1 且交换未禁用时，第一个实际产生输入并被检测到的手柄交给 P2；其输入设备替换为虚拟设备 id=1000，并映射到 P2 用户。其他手柄走自然 P1 路由。
- 手柄断开会从检测顺序列表移除。当前逻辑只区分 P1/P2，不提供 P3/P4 的独立设备分配。
- `SetPlayer` 根据 ControllerId 是否等于 1 选择 IMC_P2 或 IMC_P1。
- `SetupInputComponent` 保留非 Enhanced InputComponent 的销毁重建 workaround。
- 移动绑定 Started/Triggered/Completed；放置绑定 Started。长按默认先等待 0.3 秒，再每 0.15 秒移动一格。
- 输入取绝对值较大的轴；X 正值使 GridX−1，Y 正值使 GridY+1。不要把这套坐标关系按直觉改写。
- CursorPawn 不 Tick、无碰撞，移动限制在有效网格内，位置为地图原点加 `(X*TileSize,Y*TileSize,50)`。

箭头放置拒绝 Spawn、GoalP1、GoalP2 和外周一圈格子；教程还会追加阶段与目标格限制。双方可以覆盖对手的普通箭头。

每个 Controller 持有私有 PlaceHistory，最大长度 3。重复放置同一坐标会先移除旧记录，再加入队尾。满额时通过 `ClearArrowIfOwned` 清除最旧记录，只有当前格仍为本玩家方向箭头才会清除，避免删掉对手后续覆盖的箭头。历史记录与地图实际所有权不是同一份数据，扩展效果时必须同时考虑它们。

固定相机默认开关为 false；启用后每个 Controller 生成正交 CameraActor，XY 对齐地图中心，Z 来自 FixedCameraLocation，默认旋转 Pitch=−90、OrthoWidth=2048。也提供按 Tag 切换到已加载 Actor 的接口。

## 6. 网格与视觉

依据：`Public/GameTypes.h`、`Public/Lee/MapManager.h`、`Private/Lee/MapManager.cpp`。

ETileType 数值顺序：Empty=0，Up=1，Down=2，Left=3，Right=4，Spawn=5，GoalP1=6，GoalP2=7。方向旋转不能使用枚举加减。

FMapTileData 保存 WorldLocation、TileType、OwnerPlayerId。Owner 仅对方向格有意义，0=P1，1=P2；非方向格由 SetTileData 归零。`GetTileOwner` 对非法坐标返回 255。

GridData 索引为 `Y*MapWidth+X`，默认地图 10×10、格长 100。坐标计算基于地图位置与世界 XY 轴，没有纳入地图旋转和缩放。

渲染由基础地板 HISM、7 个状态层和额外 4 个 P2 方向层组成。方向层按 Owner 分流；颜色与材质实际配置需查蓝图。箭头 Yaw 分别 Up=180、Down=0、Left=90、Right=−90，状态层 Z 偏移为枚举值×0.1。

运行时应经 `SetTileData(X,Y,Type,Owner)` 写入，自动刷新受影响的状态层；同方向但 Owner 改变也会刷新。旋转对手箭头时必须回传原 Owner，否则默认归 P1。刷新一层仍会扫描整个 GridData 并重建该类型的实例。

OnConstruction 在格子总数不匹配时清空重建，否则刷新状态视觉。修改 MapWidth、MapHeight、TileSize 会触发 ResetAndGenerateBlankMap，清空已配置地图；编辑格子的属性改变会立即应用编辑。本次未触发这些入口。

## 7. 动物与生成器

依据：`Private/Takeuchi/Pawn/AnimalBase.cpp`、`Private/Takeuchi/Actor/AnimalSpawner.cpp`。

AnimalSpawner 默认每 3 秒尝试生成，单个生成器最多 5 个有效动物，BeginPlay 自启默认 false。StartSpawning 先立即尝试生成一只，然后设置循环计时器；重复启动活动计时器时直接返回。生成前清理已失效对象，EndPlay 停止生成计时器。

生成位置是独立的世界坐标 SpawnLocation，不读取 Spawn 格，也不默认使用生成器自身位置。AnimalClass 是 APawn 子类；若实际是 AnimalBase，则注入 MapActor。动物 TileSize 独立存储，生成器不会同步它与地图格长。

AnimalBase 是 APawn，没有路径搜索。BeginPlay 查找地图并随机选四个世界轴方向，InitialMoveDirection 属性未参与选择。默认 MoveSpeed=100、DirectionReadTolerance=10、FacingYawOffset=−90。

Tick 先读格，再移动。用 RoundToInt 找最近格中心，同格去重；中心距离不超过 `max(DirectionReadTolerance,MoveSpeed*DeltaTime*2)` 时吸附到中心并读接口。

| 方向格 | 世界移动方向 |
|---|---|
| DirUp | +Y |
| DirDown | −Y |
| DirLeft | +X |
| DirRight | −X |

Empty/Spawn 保持当前方向；Goal 调用 MainGameMode.AddScore(0/1,1)，播放 GoalSound 后 Destroy。移动调用 `AddActorWorldOffset(MoveDelta,true)`，第二参数启用了 sweep；源码注释对碰撞的描述与调用不一致，实际效果取决于根组件及资产碰撞设置。

## 9. 教程实现

依据：`Lee/TutorialGameMode`、`TutorialHUDWidget`、`TutorialHighlightActor` 的头文件和实现。

教程继承 MainGameMode，但 BeginPlay 特意跳过 MainGameMode::BeginPlay，直接执行分辨率基类 BeginPlay。它独立创建 P2、取得地图、铺预设路线、创建教程 HUD、进入 Intro，再开启轮询。不执行普通比赛倒计时、限时或普通 HUD 初始化。

```text
Intro → MoveCursor → PlaceArrow → ScoreGoal → Complete → LV_MainGame
```

Intro 默认 3 秒；条件每 0.2 秒检查，首次延迟 0.5 秒；双方同时满足当前步骤后推进。完成状态是当前条件而非永久锁存，离开目标格会撤回移动完成标记。ScoreGoal 则比较进入该步骤时记录的分数基线。

默认 P1 目标=(3,1)，方向 Down，Goal=(3,0)；P2 目标=(8,4)，方向 Up，Goal=(8,5)。预铺路线使用到 X=11、Y=5，因此地图至少需要 12×6；与 MapManager 的 10×10 默认值不一致，教程关卡配置必须核实。

Steps 虽为数组，`GetCurrentStepDef` 当前始终只读第一个元素。Intro/Complete 禁止放置；其他练习阶段只允许本人目标格。进入 ScoreGoal 启动关卡内所有 AnimalSpawner，区别于普通比赛只控制一个生成器。

Complete 停止步骤轮询、清理高亮、广播完成；默认等 3 秒跳 LV_MainGame。没有明确停止教程生成器，切关卡时由 EndPlay 停止。

TutorialHUDWidget 绑定步骤、完成状态与完成事件，并在 NativeDestruct 解绑；ShowStep、SetPlayerReady、ShowComplete 由蓝图实现。高亮用薄立方体、动态材质 HighlightColor 参数和呼吸缩放；光标站在本人高亮格时隐藏该高亮。

## 10. 独立小游戏

依据：`Tanimura/MiniGame` 全部源码。关卡文件为 `/Game/MiniGame/Maps/LV_IceStage`。

AMiniGameMode 直接继承 AGameModeBase，配置 2～4 人，默认 2。使用 PenguinController，并在构造中加载 BP_PlayerCharacter。BeginPlay 延迟创建额外玩家，再进行 Pawn 补建与共享相机同步。

AlivePlayers 管理存活 Controller；角色 Die 广播后移除，剩余少于 2 人时广播 OnMatchEnd，平局 WinnerIndex=−1。当前 GetPlayerIndex 优先使用 AlivePlayers 的现有数组下标，删除玩家会使下标变化；胜者标识与原始玩家编号是否一致需要实测。

PlayerCharacter 提供 CharacterMovement、移动、跳跃、死亡、颜色圆盘和 bIsMoving 动画状态。默认速度 300、跳跃速度 350、转身速率 720。输入 Action 和 IMC 在 C++ 动态构建，映射 WASD、方向键、手柄左摇杆，跳跃为空格或手柄底部按钮；Content 中同名 Input 资产不能直接视为实际使用来源。

GridTileManager 默认 16×9、间距100，动态生成格子和八方向移动危险区域；危险区域先 Warning，再 ActiveHazard，临近消失时 ExpiringHazard，边缘反射。移动与生成间隔随时间缩短。GridTile 在危险状态发生 BeginOverlap 时通过 DamageableInterface 致死角色；已经重叠的角色在格子变危险时是否受到伤害，需核实资产或补充逻辑。

小游戏方向 Left=−X、Right=+X，与主玩法相反，不能共用未做转换的方向映射。全局 Viewport 只有双人路由，源码的四人数量支持并不代表四台输入设备可独立操作。

## 13. 已发现的风险与验证边界

下表记录技能代码阶段开始前的风险快照。本轮已在源码中修复主玩法阶段封锁、结算计分、结束重入、多生成器控制、越界读格和格长同步，并通过两目标编译；实机行为尚未验证。编译与实机验证状态以第 12 节及技能实施资料第 19 节为准，其余风险仍需现场核对。

| 事项 | 直接证据与可能影响 |
|---|---|
| 主玩法输入阶段缺口 | SetPlayersInputEnabled 仅设置 IgnoreMove/Look；光标直接改位置、放置回调没有读取这些标志。不能宣称倒计时或结束阶段已可靠封锁操作 |
| 结算后的得分 | EndGame 不冻结现存动物、不限制 AddScore；GameInstance 保存后到切关卡之间仍可能进球，显示比分与保存结果可能不同 |
| EndGame 可重入 | 没有结束状态锁；从蓝图提前调用也没有统一清除 Ready/GameTimer。后续修改需考虑全部入口 |
| 生成器控制范围 | 正常比赛只缓存和控制第一个生成器；多生成器、自动启动配置可能绕过比赛时序 |
| 读格越界 | GetCellState 仅检查线性索引，未分别验证 X/Y；部分越界坐标会落到另一行的有效索引。动物没有独立边界停止或回收逻辑 |
| 格长不一致 | AnimalBase 与 MapManager 各有 TileSize；生成时未同步，资产参数不同会导致读格错误 |
| 教程地图尺寸 | 默认预铺到 X=11，而 MapManager 默认宽10；必须检查教程实例 |
| HUD 初值 | 初始时间广播早于 HUD 绑定，当前是否显示正确依赖蓝图初始化 |
| 小游戏胜者编号 | AlivePlayers 删除后数组下标变化，GetPlayerIndex 优先使用变化后的下标 |
| 危险格接触判定 | 仅 BeginOverlap 触发伤害；站立期间状态变危险的处理未见 C++ 实现 |
| 四人设备路由 | 全局 Viewport 实现只区分双人，与 MiniGame 的2～4人配置存在能力差距 |
| 打包与外部对象 | 显式 Cook 地图有限，外部关卡对象被忽略；可发布内容完整性未验证 |
| 调试日志 | Viewport 每次输入 Warning 日志，可能干扰定位并增加输出量 |

以上主要来自源码静态阅读，MCP 补充发现见第15节。没有执行构建、实际输入测试、PIE 或打包，不能据此给出运行通过结论。Source 搜索未发现自动化或功能测试实现。
