## 1. 需求与已确认约束

| 项目 | 决定 |
|---|---|
| 技能分类 | ① 对地图箭头产生作用（间接影响玩家操作）；② 对动物产生作用 |
| 释放方式 | **全局按键释放**，无目标选择（作用范围是全局，或按"归属玩家"筛选） |
| 资源模型 | **有限次数**：整局每个技能 N 次，用完即废 |
| 获取方式 | **开局固定技能组**：P1/P2 在 GameMode 上各自配置一套 |

## 2. 为什么不用 GAS

GAS（Gameplay Ability System）为**网络同步的 RPG 属性系统**设计：AbilitySystemComponent、GameplayEffect、AttributeSet、GameplayTag 一整套。

本项目是本地 2P、无网络同步、技能是**离散动作**（旋转箭头/冻结动物）而非属性增减。上 GAS 意味着：每个 PC 挂 ASC、每只动物挂 ASC、效果写成 GE 资产、调试面成倍增加——收益为零。**结论：轻量自定义系统，蓝图使用者零门槛。**

明确不做：GAS、AttributeSet、GameplayTag 体系、效果叠加/互斥管理器、网络复制。

## 3. 总体架构

```
[配置层]                          [运行时层]                        [效果层]
AMainGameMode                     USkillSystemComponent             USkillDefinition
 ├─ P1Skills (资产数组)  ─初始化→   ├─ 挂在 PlayerController 上       (UPrimaryDataAsset, 抽象)
 ├─ P2Skills (资产数组)            ├─ FSkillSlot[] (剩余次数)          ├─ USkillDef_RotateOpponentArrows
 └─ StartMatch/EndGame ─开关→     ├─ bEnabled (可用开关)             └─ USkillDef_FreezeAllAnimals
                                  └─ OnSkillUsed/OnSkillDenied
```

三条职责边界：

1. **配置与编排 → `AMainGameMode`**（约 15 行改动）：持有双方的技能资产数组；`StartMatch()` 初始化组件并开启；`EndGame()` 关闭。与其现有职责一致（它已经在 StartMatch 里开输入、开 spawner）。
2. **运行时状态 → `USkillSystemComponent`**（每玩家一个，挂在 PC 上）：剩余次数、可用开关。**严禁把剩余次数放进 Definition 资产**——资产是共享实例，P1 用掉会把 P2 的同款也扣掉。
3. **效果实现 → `USkillDefinition` 子类**：每个技能一个 C++ 子类 + 一个资产实例。加新技能 = 新建子类 + 建资产，**不改任何现有文件**，团队可并行。

备选方案否决记录：

| 备选 | 否决理由 |
|---|---|
| 单 DataAsset + 技能枚举 + switch | 全部技能逻辑挤一个文件，每次加技能必改同一处（合并冲突源）；蓝图侧无法扩展 |
| 剩余次数放 WorldSubsystem/GameMode 统一管 | 玩家数据被从玩家身边拆走；GameMode 属 Tanimura，侵入面大；对本项目规模 WorldSubsystem 过度设计 |
| 动物效果走新建接口 `IAnimalEffectable` | 所有动物 BP 都直接继承 `AAnimalBase`（Takeuchi/Pawn/AnimalBase.h:11），单实现类建接口是形式主义；且冻结本来就必须改 AnimalBase 内部（Tick 短路，见 §6），接口只是多一层空转 |

## 4. 类设计

### 4.1 `SkillTypes.h`（`Public/Lee/Skill/`，共享类型）

```cpp
UENUM(BlueprintType)
enum class ESkillCategory : uint8
{
    MapTile,   // 地図の矢印に作用するスキル
    Animal     // 動物に作用するスキル
};

USTRUCT(BlueprintType)
struct FSkillSlot   // 运行时状态：技能槽 = 定义 + 剩余次数
{
    GENERATED_BODY()
    UPROPERTY(BlueprintReadOnly) TObjectPtr<USkillDefinition> Definition = nullptr;
    UPROPERTY(BlueprintReadOnly) int32 RemainingUses = 0;
};

USTRUCT(BlueprintType)
struct FSkillContext   // 施放上下文（v1 只填一半字段，为指向型技能预留）
{
    GENERATED_BODY()
    UPROPERTY(BlueprintReadOnly) uint8 CasterPlayerId = 0;   // 0=1P, 1=2P
    UPROPERTY(BlueprintReadOnly) TWeakObjectPtr<AMapManager> Map;
    UPROPERTY(BlueprintReadOnly) FIntPoint CursorGridCoords = FIntPoint(-1, -1); // 施放者光标格（预留）
};

DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(FOnSkillUsedSignature,
    uint8, PlayerId, int32, SlotIndex, int32, RemainingUses);
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(FOnSkillDeniedSignature,
    uint8, PlayerId, int32, SlotIndex);
```

委托格式照抄 `MainGameMode.h:15-21` 惯例（`DECLARE_DYNAMIC_MULTICAST_DELEGATE_Xxx` + `UPROPERTY(BlueprintAssignable)` + 广播前 `IsBound()` 判空）。

### 4.2 `USkillDefinition`（`Public/Lee/Skill/SkillDefinition.h`）

```cpp
UCLASS(Abstract, Blueprintable)
class ANIMALGATHERER_API USkillDefinition : public UPrimaryDataAsset
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="Skill") FText SkillName;
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="Skill") TSoftObjectPtr<UTexture2D> Icon;
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="Skill", meta=(ClampMin="1"))
    int32 MaxUseCount = 1;                        // 整局 N 次
    UPROPERTY(EditAnywhere, BlueprintReadOnly, Category="Skill")
    ESkillCategory Category = ESkillCategory::MapTile;

    // C++ 子类 override _Implementation；纯 BP 技能直接重写事件节点。
    // 返回「是否实际产生了效果」：对手没有箭头时返回 false → 不扣次数
    UFUNCTION(BlueprintNativeEvent, Category="Skill")
    bool ExecuteSkill(const FSkillContext& Context);
};
```

- 选 `UPrimaryDataAsset` 基类是为未来的「局内随机获取」预留 AssetManager 按主资产 ID 拉技能池的能力（§9），v1 顺手 override `GetPrimaryAssetId`（3 行）。
- `ExecuteSkill` 用 BlueprintNativeEvent：C++ 技能 override `_Implementation`；团队里不会 C++ 的成员可以直接建蓝图子类、重写事件节点做纯 BP 技能。

### 4.3 `USkillSystemComponent`（`Public/Lee/Skill/SkillSystemComponent.h`）

```cpp
UCLASS(ClassGroup=(Skill), meta=(BlueprintSpawnableComponent))
class ANIMALGATHERER_API USkillSystemComponent : public UActorComponent
{
    GENERATED_BODY()
public:
    UPROPERTY(BlueprintAssignable) FOnSkillUsedSignature   OnSkillUsed;
    UPROPERTY(BlueprintAssignable) FOnSkillDeniedSignature OnSkillDenied;

    // MainGameMode::StartMatch から PC ごとに呼ばれる
    UFUNCTION(BlueprintCallable) void InitializeSkills(uint8 InPlayerId, const TArray<USkillDefinition*>& InSkills);

    // 試合中のみ true。EndGame で必ず false にする（§11 リスク1）
    UFUNCTION(BlueprintCallable) void SetSkillsEnabled(bool bInEnabled);

    // 入力コールバックの入口：チェック → 実行 → 回数消費 → 放送
    UFUNCTION(BlueprintCallable) bool TryUseSkill(int32 SlotIndex);
    UFUNCTION(BlueprintPure)     bool CanUseSkill(int32 SlotIndex) const;

    UFUNCTION(BlueprintPure) TArray<FSkillSlot> GetSkillSlots() const;   // HUD 初期化用

private:
    UPROPERTY(VisibleAnywhere) TArray<FSkillSlot> Slots;
    uint8 PlayerId = 0;
    bool  bEnabled = false;   // デフォルト false：カウントダウン/チュートリアル/結果画面では自然に無効
    FSkillContext MakeContext() const;
};
```

**挂在 PC 上而非 GameMode 的理由**：PC 已是本项目输入汇聚点（全部 BindAction 在 `SetupInputComponent`），转发一行；状态天然按玩家归属；HUD 取数走 `GetPlayerController(i)->FindComponentByClass<USkillSystemComponent>()`。

## 5. 数据流（按键 → HUD 全链路）

```
[Content] IA_Skill_1 / IA_Skill_2，映射进 IMC_P1 / IMC_P2（键位如 P1=Q/E，P2=逗号/句号）
    │  ① EnhancedInput ETriggerEvent::Started（与现有 IA_Set_* 完全同构，
    │     SetupInputComponent 里 BindAction，PC 头文件加 IA_Skill_1/2 UPROPERTY）
    ▼
AAnimalGatherPlayerController::OnSkill1Pressed(const FInputActionValue&)
    │  ② 一行转发：SkillSystem->TryUseSkill(0 /*槽位号*/)
    ▼
③ 可用性检查（组件内 CanUseSkill）
      bEnabled == true ?                  ← 唯一可靠的开关（§11 风险1）
      Slots[SlotIndex].RemainingUses > 0 ?
      ├─ 失败 → OnSkillDenied.Broadcast(PlayerId, SlotIndex)；return false
      ▼
④ MakeContext()：PlayerId、Map=GetActorOfType<AMapManager>()、光标格（预留）
    ▼
⑤ Slots[SlotIndex].Definition->ExecuteSkill(Context)
      返回 false（如对手没箭头）→ OnSkillDenied，不扣次数
    ▼
⑥ RemainingUses--;  OnSkillUsed.Broadcast(PlayerId, SlotIndex, RemainingUses)
    ▼
⑦ HUD（照 UMyGameHUDWidget 惯例：NativeConstruct 里 AddDynamic，MyGameHUDWidget.cpp:14-22）
      OnSkillUsed → 更新对应玩家的技能图标次数/置灰
      OnSkillDenied → 播放失败提示音/图标抖动
    ▼
⑧ 效果生效面
      ├─ 箭头类：Map->SetTileData(X, Y, NewType, 原Owner)（§7）
      └─ 动物类：TActorIterator<AAnimalBase> 遍历 → ApplyFreeze(Duration)（§6）
```

`bEnabled` 默认 false 的时序覆盖：BeginPlay 倒计时阶段（未初始化/未开启）→ StartMatch 开 → EndGame 关。

### 6.2 AnimalBase 新增内容（全部用 `// 2026.XX.XX Lee start/end` 标记）

```cpp

UPROPERTY(BlueprintReadOnly, Category="Animal|SkillState")
float SpeedMultiplier = 1.0f;        // 状態なしのとき 1。MoveAnimal の位移に乗じる

```

```cpp
// Tick 层短路（关键）：
void AAnimalBase::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
    if (bMoveFrozen) return;   // 冻結中は矢印の読み取りも移動もしない（追加）
    UpdateMoveDirectionFromCurrentTile(DeltaTime);
    MoveAnimal(DeltaTime);
}
// MoveAnimal 内：MoveDelta = CurrentMoveDirection * MoveSpeed * SpeedMultiplier * DeltaTime;
```

### 6.3 为什么冻结必须在 Tick 最前短路

动物**没有任何状态概念**，且每进入新格子中心时 `UpdateMoveDirectionFromCurrentTile`（AnimalBase.cpp:81-191）会用该格箭头**覆盖** `CurrentMoveDirection`——任何「从外部改方向」的技能效果都会在下一格被冲掉。持续型干预（冻结/减速）必须在 Tick 入口拦截。

冻结在 Tick 最前短路的好处：动物被冻在两格中间时，解冻后继续走到下一格中心才读新箭头（中心距离判定 AnimalBase.cpp:117-121 保证），**无任何副作用**；冻结期间 Goal 判定也不跑（冻在 Goal 上不会得分）。

### 6.4 计时/恢复：贴合项目 timer 惯例

```cpp
void AAnimalBase::ApplyFreeze(float Duration)
{
    bMoveFrozen = true;
    GetWorldTimerManager().SetTimer(FreezeTimerHandle, this,
        &AAnimalBase::OnFreezeExpired, FMath::Max(Duration, 0.1f), false);
}
```

- 与 PC 的 `AutoRepeatHandle`（AnimalGatherPlayerController.cpp:206）、GameMode 的 `ResultDelayTimerHandle` 同款惯例：**拥有者 Actor 成员 `FTimerHandle` + 一次性回调恢复**。
- 可重入：重复施放同一效果 = 重挂 timer 覆盖旧时长，简单可预期。
- 动物中途到 Goal 被 `Destroy()`：TimerManager 对绑定已销毁对象的回调自动失效，**无需清理代码**。
- 不采用 GridTileManager 的 `GetTimerElapsed` 平滑改周期模式——那是给「循环 timer 中途改周期」设计的，冻结是一次性 timer，直接 SetTimer。

## 7. 箭头效果实现要点

### 7.1 唯一写入入口

`AMapManager::SetTileData(int32 X, int32 Y, ETileType NewType, uint8 InOwnerPlayerId = 0)`（MapManager.h:119，BlueprintCallable）——运行时改单格的唯一入口，内部自动只重建受影响的视觉层。**禁止**运行时调 `UpdateMapVisuals()`（全层重建会闪）。

### 7.2 两个必踩的坑（已核实源码）

1. **旋转必须用显式映射 switch，禁止枚举加法**。`ETileType` 声明顺序是 Up(1)/Down(2)/Left(3)/Right(4)（GameTypes.h:15-19），「顺时针 +1」的枚举算术会得到 Up→Down（转 180°）。
2. **必须回传原 Owner**。`SetTileData` 内部 `const uint8 NewOwner = IsDirectionTile(NewType) ? InOwnerPlayerId : 0;`（MapManager.cpp:106-114）会重算所有权——漏传第 4 参会让对手箭头所有权静默归 0：颜色丢失（渲染按 Owner 分流到 P1 蓝/P2 红 HISM 层，MapManager.cpp:242-244）、后续 `ClearArrowIfOwned` 行为错乱。

### 7.3 遍历与筛选

`GridData` 是公开 `TArray<FMapTileData>`（索引 `Y * MapWidth + X`），遍历过滤 `IsDirectionTile(Type) && OwnerPlayerId == 对手`。场上箭头上限 3×2=6 条（FIFO MaxHistory=3，AnimalGatherPlayerController.cpp:339），一帧遍历 100 格 + ≤6 次 SetTileData，性能可忽略。

### 7.4 与 PlaceHistory（对手 FIFO）的相容性（已逐条论证）

| 技能操作 | FIFO 满期时 `ClearArrowIfOwned(旧坐标, 对手Owner)` 的行为 |
|---|---|
| 旋转对手箭头（Owner 不变） | 照常命中，箭头正常消退 ✓ |
| 偷取对手箭头（Owner 改变） | Owner 不匹配拒绝清除（MapManager.cpp:148-154 本来就是防误删设计）✓ |
| 删除对手箭头 | 满期清除变 no-op ✓ |
| **凭空给某玩家添加箭头** | **该格不在其 PlaceHistory → 永不过期，破坏 FIFO 语义 ✗** |

**效果设计约束（写进规范）：效果只允许旋转/偷取/删除，禁止凭空添加箭头。** 若未来必须添加，需同步操作对方 PlaceHistory（private，需加受控接口）。

### 7.5 旋转映射（显式 switch）

```cpp
static ETileType RotateDirectionClockwise(ETileType Type, int32 Steps)
{
    switch (Type) {
    case ETileType::DirUp:    return ETileType::DirRight;   // 上 → 右
    case ETileType::DirRight: return ETileType::DirDown;    // 右 → 下
    case ETileType::DirDown:  return ETileType::DirLeft;    // 下 → 左
    case ETileType::DirLeft:  return ETileType::DirUp;      // 左 → 上
    default: return Type;        // Empty/Spawn/Goal/未来新格型 原样返回
    }
}
```

收敛在一个 static 函数的原因：本项目的「视觉方向」与世界轴的对应关系有反直觉之处——`DirLeft` 推动物体朝世界 +X、`DirRight` 朝 −X（AnimalBase.cpp:144-150），光标输入 X 正方向却对应 GridX−1（AnimalGatherPlayerController.cpp:239-247）。**俯视相机下「顺时针」在屏幕上是顺还是逆必须进 PIE 实测**；收敛后实测反了只改这一处。

## 8. 示例技能（具体技能清单后续可调，此两个用于验证架构）

### 8.1 箭头类：`USkillDef_RotateOpponentArrows`——对手全部箭头顺时针旋转 90°

```cpp
UCLASS(Blueprintable)
class ANIMALGATHERER_API USkillDef_RotateOpponentArrows : public USkillDefinition
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, Category="Rotate", meta=(ClampMin="1"))
    int32 RotationSteps = 1;     // 1 = +90°, 2 = 180°
    virtual bool ExecuteSkill_Implementation(const FSkillContext& Context) override;

```

执行流程：`GetActorOfClass<AMapManager>()` → 遍历 GridData 过滤对手方向格 → 逐格 `SetTileData(X, Y, Rotate(...), 该格原Owner)` → 一格都没改（对手没箭头）返回 false 不扣次数。

### 8.2 动物类：`USkillDef_FreezeAllAnimals`——全体动物冻结 2 秒

```cpp
UCLASS(Blueprintable)
class ANIMALGATHERER_API USkillDef_FreezeAllAnimals : public USkillDefinition
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, Category="Freeze", meta=(ClampMin="0.1", Units="s"))
    float FreezeDuration = 2.0f;
    virtual bool ExecuteSkill_Implementation(const FSkillContext& Context) override;
};
```

执行流程：`for (TActorIterator<AAnimalBase> It(GetWorld()); It; ++It) It->ApplyFreeze(FreezeDuration)`。BP 子类（BP_Animal 等）直接继承 AAnimalBase，都会被枚举到；场上 ≤10 只按次扫描无性能问题。动物是中立资源，冻结对称作用于双方——这是本作的机制决定的（动物没有归属）。

视听反馈（可选，BP 侧做）：AnimalBase 可加 `FOnAnimalFrozen(bool)` BlueprintAssignable 广播（照 MainGameMode 委托惯例），动画 BP 据此挂特效音效。v1 可先不做，`IsMoveFrozen()` 轮询够用。

## 11. 风险与注意点

1. **EndGame 输入缺口（既有问题）**：`EndGame()`（MainGameMode.cpp:117-145）没有禁输入，且 `SetPlayersInputEnabled` 用 `SetIgnoreMoveInput/SetIgnoreLookInput`（:92-101），**挡不住 EnhancedInput 的 BindAction 回调**——箭头放置键在 TimeUp 后 1 秒（TimeUpDelay）内本来就能按，是既有缺口。技能侧对策：组件 `bEnabled` 自己把关，不依赖引擎输入开关。移动输入的缺口建议**另开任务知会 Tanimura**，不在本功能内修。
2. **旋转的屏幕方向必须实测**：§7.5 所述坐标系反直觉，「顺时针」在屏幕上是否真是顺时针要进 PIE 确认；映射收敛在一个函数里，反了对调 return 值即可。
3. **TileType 扩展破坏面**：未来加新格型（陷阱/冰面）要同时动 GameTypes.h 枚举、AnimalBase.cpp:134-190 switch、MapManager 刷新逻辑。技能侧坚持用 `IsDirectionTile()` 过滤 + 旋转函数 `default: return Type;`，新格型出现时自动跳过，不会误转。
4. **PlayerId 类型混用**：项目里 `uint8`（Owner/GetTileOwner，255=越界哨兵）与 `int32`（CursorPawn::PlayerID）并存。技能 API **统一用 uint8**，ControllerId 换算处照抄 PC `SetPlayer` 的 `ControllerId == 1 ? 1 : 0`（AnimalGatherPlayerController.cpp:129），只写一次。
5. **一帧多次 SetTileData 的刷新成本**：每次调用触发一层 `RefreshStateVisual` 全层实例重建；旋转技能一帧最多 ~6 格，可接受。**现在不做批量刷新优化**，真卡了再说。
6. **SpeedMultiplier 与方向读取容差的交互**：`UpdateMoveDirectionFromCurrentTile` 里帧移动距离 `MoveSpeed * DeltaTime`（AnimalBase.cpp:113）用于容差放大，严格来说也应乘 Multiplier；冻结时整段跳过天然无此问题。**实施时与 Takeuchi 确认这一行**。
7. **冻结与结算的时序**：TimeUp 后 TimeUpDelay 1 秒内动物可能仍处冻结态，随后 OpenLevel 切关卡、timer 随对象销毁自动失效，无泄漏。
