# 本轮运行验收方法补充

通过编辑器Cmd执行器在PIE World调用公开函数，暂停只冻结游戏时钟便于读取3秒效果；命令返回true仅代表UI提交，结果以Slots日志、GridData回读、共享效果属性及截图为准。多玩家同时调用采用ke原生类，实例调用采用完整PIE对象路径。所有操作只作用于PIE实例，绝不保存到关卡。

动画核查：UE5.8 SkeletalMeshComponent.cpp:4399 的 SetPlayRate 调用SingleNodeInstance.SetPlayRate，并不更新组件AnimationData.savedPlayRate。因此后者是保存/初始化配置，不能当实际播放倍率读数。本轮不用该值判定运行动画成功或失败；事件连线和组件模式可独立验证，实际倍率若没有可靠运行读取能力，留为待人工确认。

实际已验证（控制台/API方式）：Ready尝试加速，双方均保持2次；Playing双方同时成功后共享1.5倍，两人各剩1次且CD截止相同。无目标反向/冷却中再次加速均未扣次。P2三格(10,10)Up/(9,10)Left/(8,10)Down被P1反向为Down/Right/Up，仍Owner1；P1只消耗自己反向1次。P2第四箭头(7,10)Right清最旧(10,10)，其他反向方向保留；P1覆盖(8,10)为Up后，P2继续FIFO淘汰旧(8,10)记录没有清P1箭头。运行Map回读为MCP-Map-ReversedVerified/FIFO-Fourth/FIFO-OverwriteProtection。

恢复时钟6秒后共享倍率1/截止0；P1第二次加速后其UI记录0次、P2仍1次；调用EndGame后Ended、倍率1/截止0，再次两边尝试均未消费。直接调用EndGame测试不等同于自然截止精确帧测试。HUD RemoveFromParent/AddToViewport调用成功，四卡运行LastReportedUses=[P1反向1,P1加速0,P2反向2,P2加速1]，未补充次数。恢复时钟后实际Result显示0:1与P2胜利。本局全程只有一份运行主HUD（obj list实际Count=1）。

失败提示静态接线复查发现HideFailP1/P2事件均空，实机Ready失败提示残留到Playing，已交GLM修正；前期Timer存在检查不足，不能计为提示清除通过。验收辅助脚本首次两处格式错误已修正：PowerShell插值冒号需花括号；programmatic run必须dict，不能list。前次map读取失败不代表玩法错误，以修正后的Verified回读为准。
